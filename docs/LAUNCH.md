# การตั้งค่า BBP Center สำหรับใช้งานจริง

## สิ่งที่เปลี่ยนในรอบนี้ (2026-11-03)

ลบแผงทดลอง สลับผู้ใช้/เจ้าของร้าน ปรับยอด เลื่อนเวลา QR ปลอม สลิปจำลอง สินค้า/รีวิว/ข้อมูลส่งมอบปลอม และการสมัคร/เข้าสู่ระบบที่รับรหัสผ่านใดก็ได้แล้ว

หน้าเว็บทุกส่วนใช้บัญชีและฐานข้อมูลของ server กระเป๋าเงินอยู่ที่ `/wallet` (ลิงก์ `/wallet/live` เดิมยัง redirect ได้) การซื้อ จอง ชำระส่วนที่เหลือ และสั่งฟาร์มหักยอดบน server เท่านั้น ไม่มี state เงินหรือสินค้าใน localStorage

สินค้าจริงเริ่มว่าง ผู้ใช้เดิมและยอดเงินจริงใน SQLite เดิมไม่ถูกลบ กฎจอง 50%, 12+2 ชั่วโมง, ริบเงินจอง, cooldown 6 ชั่วโมง และราคาฟาร์มตารางเดิมได้รับการยืนยันจากเจ้าของในแชตแล้ว

## 1. รันระบบ

ต้องมี Node.js 24+

ใน `server/`: `npm ci` แล้วตั้ง `server/.env` จาก `.env.example` โดยคงเบอร์และ OAuth credentials ที่ตั้งไว้แล้ว

ใน `app/`: `npm ci` และ `npm run build`

รัน `npm start` จาก `server/` สำหรับ backend/ไฟล์ frontend ที่ build แล้ว ระบบฟัง loopback port 3001

ขณะพัฒนา รัน `npm run dev` อีก terminal ใน `app/` แล้วเปิด `http://localhost:5173` ให้ `APP_ORIGIN` ตรง URL ที่เปิด ใช้ Google/Discord redirect URI เดิมตาม `OAUTH_SETUP.md`

## 2. ตั้งบัญชีเจ้าของร้าน

1. เข้าสู่ระบบด้วยบัญชีที่คุณจะใช้ดูแลร้าน
2. เปิด `/account/profile` แล้วคัดลอก **รหัสบัญชี** (UUID)
3. ใส่ใน `.env`: `ADMIN_USER_IDS=รหัสบัญชีของคุณ` รองรับหลายบัญชีโดยคั่นด้วยจุลภาค
4. Restart Node server แล้วโหลดเว็บใหม่
5. เปิด `/owner` จะเห็นหลังบ้าน

ใช้รหัสบัญชีที่คัดลอกจากบัญชีคุณเท่านั้น ระบบไม่ยกระดับสิทธิ์จากอีเมล ชื่อบัญชี localStorage หรือค่าที่ browser ส่งมา เมื่อยังไม่ตั้ง `ADMIN_USER_IDS` จะไม่มีบัญชีใดเข้าหลังบ้านได้

## 3. ใส่ข้อมูลร้านจริงก่อนเปิดรับเงิน

ใน `/owner` → ตั้งค่าร้าน ใส่ลิงก์ติดต่อ HTTPS และเงื่อนไขร้าน หากจะรับฟาร์ม ให้กรอกเงื่อนไขฟาร์ม รวมการประสานงาน การยกเลิกและคืนเงินด้วย ไม่กรอกเงื่อนไขฟาร์มจะสั่งฟาร์มไม่ได้

เพิ่มไอดีจากแท็บสินค้า: ชื่อ หมวด ราคา ภาพจริงผ่าน HTTPS รายละเอียด เงื่อนไขการโอน การรับประกัน และข้อมูลส่งมอบ แต่ละรายการมีสต็อกหนึ่งบัญชี ถ้าต้องถอนสินค้าที่พร้อมขายใช้ปุ่มหยุดขาย ไม่สามารถถอนสินค้าที่จองหรือขายแล้ว

ข้อมูลส่งมอบเข้ารหัส AES-256-GCM เปิดผ่าน API เฉพาะผู้ซื้อที่ชำระครบและบันทึก audit log ไม่อยู่ใน catalog หรือ response หน้าสินค้า

จากนั้นเปิด checkbox **เปิดรับคำสั่งซื้อและเติมเงิน** แล้วบันทึก ระบบจะไม่ให้ซื้อหรือรับซองเมื่อร้านยังปิด

TrueMoney ต้องมี `TRUEMONEY_RECIPIENT_PHONE` และ `TRUEMONEY_ENABLED=true` แล้ว restart server ระบบไม่มีช่องตรวจสลิปธนาคารจนกว่าจะมี provider จริง

## 4. งานฟาร์มและรายการรอตรวจสอบ

หลังบ้านงานฟาร์มอัปเดตสถานะและจำนวนเพชรที่วัดได้จริง ความคืบหน้าไม่เพิ่มตามเวลา ลูกค้าดู timeline ในบัญชี การประสานเข้าถึงบัญชีใช้ช่องทางร้านที่คุณกำหนด ไม่มีการขอรหัสผ่าน/OTP/backup code ของเกมในแบบฟอร์มเว็บ

หากรับซองแล้ว timeout หรือไม่ทราบผล จะเป็นรายการรอตรวจสอบ ระบบไม่ redeem ซ้ำเอง เจ้าของต้องตรวจเงินเข้ากับผู้ให้บริการก่อนจึงกรอกยอดและเลขอ้างอิงหลักฐานในแท็บตรวจยอดรับเงิน หลักฐานซ้ำหรือรายการที่ตรวจแล้วเพิ่มยอดซ้ำไม่ได้ ทุกครั้งมี audit log

## 5. ข้อมูลสำคัญและการขึ้นโดเมนจริง

เก็บ `server/data/bbp.sqlite` และไฟล์ SQLite ที่เกี่ยวข้องบน persistent disk ไฟล์ `server/data/delivery.key` สร้างอัตโนมัติเมื่อเริ่ม server ครั้งแรก ต้องสำรอง key คู่ฐานข้อมูลและจำกัดสิทธิ์ หาก key หายจะถอดข้อมูลส่งมอบเดิมไม่ได้ ห้าม commit `.env`, DB หรือ key

สำรองด้วย SQLite online backup หรือหยุด server ก่อนคัดลอกโฟลเดอร์ข้อมูล เก็บสำรองในพื้นที่จำกัดสิทธิ์ ไม่คัดลอก DB ที่กำลังเขียนแบบละเลย WAL

การเปิดบนอินเทอร์เน็ตต้องมีโดเมน/โฮสต์และ HTTPS: ตั้ง `NODE_ENV=production` และ `APP_ORIGIN=https://โดเมนร้าน` ให้ reverse proxy ส่งทั้งเว็บและ `/api/*` มายัง `127.0.0.1:3001` จากนั้นเพิ่ม redirect URI ของโดเมนจริงใน Google และ Discord ตามคู่มือ OAuth ไม่เปิด Node/SQLite ตรงสู่สาธารณะ

GitHub เก็บ source code การ push ไม่ได้ deploy Node server, ฐานข้อมูล หรือ HTTPS ให้เอง

## การตรวจสอบ

ผลตรวจรอบ 2026-11-03: server ผ่าน 21 เทส, frontend ผ่าน 10 เทส และ production build สำเร็จ ตรวจหน้าร้าน/หน้าฟาร์มที่ความกว้าง 360px ไม่มีเนื้อหาล้นแนวนอน และผู้ไม่เข้าสู่ระบบเข้าใช้งานหลังบ้านไม่ได้

`app/`: `npm test` และ `npm run build`

`server/`: `npm test` (ให้ build frontend ก่อนสำหรับ static-serving test)

เทสใช้ DB แยก/ชั่วคราวและ provider จำลองเฉพาะใน `server/test/` ไม่อยู่ใน UI และไม่ส่งซองจริง ครอบคลุมซื้อชนกัน หักยอดครั้งเดียว จอง/grace/expiry/cooldown สิทธิ์ข้อมูลส่งมอบ farm progress OAuth และรับซองซ้ำ

ยังต้องให้เจ้าของยืนยันการล็อกอิน Google/Discord บนโดเมนที่จะใช้ และทำรายการรับซองจริงด้วยตนเองก่อนเชิญลูกค้า ไม่มีการเคลื่อนเงินจริงระหว่างการพัฒนารอบนี้
